# Trap Runner

Мультиплеерный Deathrun для Roblox: один игрок — **Трапер** — бежит по параллельному коридору
за стеклом и включает ловушки, остальные — **Раннеры** — проходят полосу препятствий.
Трасса собирается заново каждый раунд. Весь текст в игре — на русском (шрифт SourceSans, с кириллицей).
Трапер бегает в 3 раза быстрее раннеров (48 против 16) по коридору шириной 20 studs.

**Статус: Фаза 3 — ловушки.** Трасса из 24–32 сегментов: ловушки чередуются со связками (связка после
каждых 2–3 ловушек), сложность растёт к финишу, каждые 6 сегментов — чекпоинт-ворота, одна из 4 тем.
Готовы 5 ловушек с кнопками в коридоре Трапера, kill feed и режим зрителя.

## Проверка на ПК (Windows)

### Способ 1: готовый файл места, ничего не устанавливая

1. Возьми `TrapRunner.rbxlx` (или собери сам: `rojo build default.project.json -o TrapRunner.rbxlx`).
2. Открой его в Roblox Studio: двойной клик по файлу или **File → Open from File**.
   В режиме редактирования мир пустой — лобби и трасса строятся скриптами при запуске.
3. Вкладка **Test** → блок **Clients and Servers**: выбери **Local Server**, **3 Players** → **Start**.
   Откроются 4 окна: сервер и 3 клиента. На слабом ПК хватит 2 игроков (минимум для раунда).
4. В каждом окне клиента дойди до круга: синий — RUNNER, красный — TRAPPER.
5. В окне сервера открой **View → Output**: там `[Main] Trap Runner server started`,
   `[Track] seed = …`, `[Round] Over: …`. Ошибки показываются красным.
6. Закончить тест: кнопка **Cleanup** (Stop) в окне сервера.

Этот способ годится, чтобы посмотреть игру. Изменения, сделанные в Studio, в репозиторий не попадут.

### Способ 2: живая синхронизация через Rojo (для разработки)

1. Установи Rojo: `winget install Rojo.Rojo` или архив со страницы
   [Rojo Releases](https://github.com/rojo-rbx/rojo/releases).
   Можно через [Rokit](https://github.com/rojo-rbx/rokit): `winget install Rojo.Rokit`, затем в папке проекта
   `rokit install` (поставит Rojo, StyLua и Selene из `rokit.toml`).
2. Скачай проект: `git clone -b claude/roblox-game-y43pbn https://github.com/spremakrolik-png/Roblox`
   или **Code → Download ZIP** на странице ветки.
3. В папке проекта один раз выполни `rojo plugin install` (ставит плагин Rojo в Studio), потом `rojo serve`.
4. В Studio создай место из шаблона **Baseplate**, на вкладке **Plugins** нажми **Rojo → Connect**.
   Скрипты появятся в Studio и будут обновляться при каждом сохранении файла.
5. Проверь, что у `Workspace` включён **StreamingEnabled** (Rojo выставляет его сам; если нет — поставь вручную).
6. Запусти тест, как в шаге 3 первого способа.

Лимит 12 игроков задаётся в Game Settings → Places → Max Players (после публикации).

## Как проверить Фазу 1

В тесте с 3 клиентами:

| Сценарий | Что должно произойти |
|---|---|
| Двое встали в синий круг РАННЕР, один в красный ТРАПЕР | 10 c «Следующий раунд через…», потом 15 c отсчёта: у каждого в HUD своя роль, далеко по оси X строится трасса |
| Конец отсчёта | Раннеры на стартовой площадке, Трапер в коридоре за стеклом; 3 c все заморожены, ворота исчезают, баннеры «БЕГИ!» / «ТЫ ТРАПЕР — останови их всех!» |
| Раннеры добегают до финиша | В kill feed «Name финиширует: 1 место (0:42.3)», места 1-2-3 по порядку пересечения финиша |
| Раннер прыгает в пропасть | «Name падает в пропасть», он появляется в лобби, раунд идёт дальше |
| Все раннеры погибли | «ПОБЕДА ТРАПЕРА!» на экране итогов |
| Раннер стоит на месте 25 c | «Name выбывает (AFK)», его переносит в лобби, раунд не зависает |
| Трапер закрыл окно клиента посреди раунда | Раунд сразу заканчивается, оставшиеся раннеры отмечены «в живых», победа Раннеров |
| В кругах меньше 2 игроков | На табло и в HUD: «Встань в круг, чтобы играть» |
| Игрок стоит вне кругов при старте отсчёта | Он не участвует и остаётся в лобби зрителем |

Правила выбора Трапера: случайный из круга TRAPPER; если там пусто — случайный из всех участников;
тот же игрок не становится Трапером два раунда подряд, если есть другие кандидаты (кроме случая, когда в круге
TRAPPER стоит только он сам).

Каждая трасса пишет в Output свой seed, тему и список сегментов:
`[Track] seed = 123456, theme = Ледяная пещера, 27 segments: JumpPlatforms1, UpDownHops1, ...`.
Чтобы воспроизвести трассу, впиши этот seed в `GameConfig.Track.DebugSeed` (0 — снова случайные трассы).
Технический лимит раунда (12 минут) закрывает раунд без наград и пишет предупреждение с seed.

## Как проверить Фазу 2

| Что проверить | Что должно быть |
|---|---|
| Несколько раундов подряд | Каждый раз другие сегменты, длина 24–32, одна из 4 тем (название — в HUD во время отсчёта) |
| Сложность | В начале широкие платформы и ступени, к финишу узкие балки, мелкие камни и тонкие столбы |
| Чекпоинты | Неоновые арки «ЧЕКПОИНТ n/N» каждые 6 сегментов; в HUD «Чекпоинт 2/4» |
| Коридор Трапера | Идёт за стеклом вдоль всей трассы от старта до финиша, без прыжков |
| Проходимость | Любой сегмент проходится обычными прыжками (проверено симуляцией: 24 варианта × 300 сидов) |
| Античит | Если раннер пробежал между чекпоинтами быстрее физически возможного (телепорт, спидхак), на финише он «Name: дисквалификация», в Output — `[AntiCheat] ...` |

## Как проверить Фазу 3

Чтобы прогнать все пять ловушек подряд, впиши в `GameConfig.Track.DebugSegments`
`{ "LavaFloor1", "VanishingBlocks2", "ClosingZone2", "CrushingWalls1", "Pistons2" }` (пустой список — обычная
случайная трасса). Тест: 2–3 игрока, один встаёт в красный круг.

| Ловушка | Как сработает (после 0.6–0.8 c мигания и надписи «!! Название ловушки !!» у раннеров в зоне) | Как выжить |
|---|---|---|
| Лавовый пол (LavaFloor) | Пол становится лавой на 3 c | Запрыгнуть на жёлтый блок или выбежать из сегмента |
| Исчезающие блоки (VanishingBlocks) | Ряды плит исчезают волной от начала к концу, через 3 c возвращаются | Успеть добежать до конца |
| Закрывающаяся зона (ClosingZone) | Ворота закрываются, комната заполняется ядом за 2 c | Не быть внутри, когда ворота закрылись |
| Давящие стены (CrushingWalls) | Стены съезжаются к центру | Выбежать вперёд или назад за ~1 c |
| Поршни (Pistons) | Поршни бьют поперёк дорожки и сталкивают в пропасть | Стоять в промежутке между поршнями |

- **Кнопки**: у начала каждого сегмента-ловушки, у дальней стены коридора. Нажать E (или тапнуть) можно
  только Траперу, только рядом и только один раз — потом кнопка серая «ИСПОЛЬЗОВАНО». Раннеры до кнопок не дотягиваются.
- **Kill feed**: «Давящие стены раздавили Name»; падение после удара ловушкой тоже засчитывается Траперу
  («Поршни столкнули в пропасть Name»). Число убийств Трапера — на экране итогов.
- **Зритель**: погибший Раннер сразу смотрит на живых; стрелки `<` `>` (или Q/E) переключают между живыми
  Раннерами и Трапером, `X` — выйти. Финишировавшие и игроки в лобби могут нажать СМОТРЕТЬ.

## Структура

```
default.project.json        Rojo: src/shared -> ReplicatedStorage.Shared,
                            src/server -> ServerScriptService.Server,
                            src/client -> StarterPlayer.StarterPlayerScripts.Client
src/
  shared/
    Types.luau              общие типы
    Remotes.luau            все RemoteEvent (только сервер -> клиент)
    GameState.luau          реплицируемое состояние: атрибуты папки ReplicatedStorage.GameState и игроков
    StatusText.luau         строки статуса для табло и HUD
    JumpMath.luau           лимиты прыжка из JumpPower/WalkSpeed/Gravity с запасом 15%
    Config/
      GameConfig.luau       таймеры, скорости, размеры лобби и трассы
      Traps.luau            тайминги ловушек, тексты kill feed
      Segments.luau         библиотека сегментов: id, builder, length, rise, difficulty, trapType, weight,
                            minDifficultyTier, params (варианты одного семейства по сложности)
  server/
    Main.server.luau
    Services/
      CharacterService.luau коллизии игроков, прыжок/скорость, телепорты
      LobbyService.luau     лобби, круги ролей, выбор Трапера, ожидание игроков, табло
      RoundService.luau     отсчёт, раунд, прогресс, чекпоинты, финиш, AFK, итоги
      TrapService.luau      кнопки ловушек, проверка нажатий, запуск ловушек, отталкивание
      SpectateService.luau  проверка запросов зрителя, подгрузка мира вокруг наблюдаемого
    Track/
      TrackPlanner.luau     выбор сегментов по seed: длина, сложность по третям, повторы, чекпоинты
      TrackGenerator.luau   постройка: старт, сегменты, чекпоинт-ворота, финиш, стекло, коридор, декор
      SegmentKit.luau       общие кирпичики для сегментов
      Themes.luau           Лавовый храм, Неоновый город, Ледяная пещера, Конфетная фабрика
      TrapKit.luau          общие части ловушек: зоны, мигание, смертельные зоны, движение
      Segments/             по модулю на семейство сегментов и на каждую ловушку
    Util/
      Build.luau            постройка из примитивов
      Assets.luau           поиск готовых моделей в ReplicatedStorage.Assets
  client/
    Main.client.luau
    Controllers/
      HUDController.luau    статус, баннер роли, отсчёт ворот, kill feed, итоги
      LobbyController.luau  подсказка, в каком круге стоит игрок
      EffectsController.luau предупреждение о ловушке, вспышка при смерти
      SpectateController.luau камера зрителя, переключение кнопками
    Util/UI.luau
```

## Свои модели вместо плейсхолдеров

Положи модель в `ReplicatedStorage.Assets` (папку создаёт Rojo и не трогает её содержимое):

- `Lobby` — должна содержать части `RunnerCircle` и `TrapperCircle` (радиус берётся из атрибута `Radius`
  или из конфига), по желанию `Board` (табло рисуется на грани Front) и `SpawnLocation`.
- `Segment_<id>` (например, `Segment_JumpPlatforms`) — pivot модели в центре пола на входе, взгляд вперёд
  по трассе; длина и перепад высоты должны совпадать с `Config/Segments.luau`. Стекло и коридор Трапера
  генератор добавит сам.

Если модели нет или в ней не хватает обязательных частей — строится плейсхолдер из примитивов.
